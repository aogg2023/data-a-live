# USB 串口（DWC3 CDC ACM 调试日志）— 2026-11-05 移植记录

本机（OnePlus 13T / songyuan / SM8850）没有 `pandora_usb.c` 与 `bsd/dev/qcomusb/`，iOS 下没有 USB 调试口。
本记录是从 data-a-live-new（Xiaomi 17 Pro / pandora，同 SM8850）移植过来的完整过程、证据与未完成项。

## 1. 旧实现（ref/data-a-live-new，已真机验证过）

- 源码：`wsl/qcomusb/`（QcomXnuUsbDebug，来自 nabu-usb-cdc，MIT；DWC3 轮询式设备驱动）+ `wsl/pandora_usb.c`（入口）；
- 启动参数：`pandora_usb=2 qcom-usb-debug=1`；
- 枚举身份：**VID 1209 / PID 316D**（CDC ACM），Windows 绑 usbser 成 COM 口；
- 实测：电脑打开 COM 后，从内核 0.000 s 到 180 s 的日志实时传到电脑，与写盘日志逐字节一致（usb4：1,525,912 字节；usb5：加上重启前 drain 后 1,544,638 字节）；
- 旧实现的 SoC 配置 `soc/Sm8850.h` 记录了交接状态：五个 USB 时钟 on、BCR=0、GDSCR=0xfa22f800、GCTL=0x00102005（device）、DCTL RUN_STOP=0、DSTS DEVCTRLHLT=1、GSNPSID=0x33313130。

## 2. 本机移植（补丁 0351）

- `xnu/patches/0351-pandora-usb.patch`（约 275 KB）：新增 23 个文件（`bsd/dev/pandora_usb.c` + `bsd/dev/qcomusb/*`，含 `soc/Sm8850.h`），并在 patch 0350 生成的 `bsd/dev/pandora_cachevol.c` 中加 `pandora_usb_init()` 调用与 extern；
- `xnu/patches/0351-pandora-usb.sh`：dxb 构建树里 `bsd/conf/files` 追加 `pandora_usb.c` 与 7 个 qcomusb 源文件（脚本先于 patch 运行，所以只能做"追加"这种无上下文编辑）；
- 入口位置：`pandora_cachevol_start()` 里、`pandora_wlan_init()` 之后；`pandora_usb_init()` 只认启动参数，参数为 0 时什么都不做。

### 依赖与注意事项

- 需要 `sweet_log_copy()`（`bsd/dev/sweet_ufs.c` 已有）；旧版"重启前把剩余日志发完"用的 `sweet_log_copy_any` 本次未移植（`pandora_usb_final` 未接入 `pl_psci_reset`）；
- 模块运行在 boot CPU 的线程里、5 ms 轮询；初始化时必须在开中断状态下先映射 GCC/DWC3/SMMU 窗口（旧补丁 0250/0251 的结论，源码里已包含）。

## 4. 已确认的根因链

1. 本机 ABL/fastboot 交接时 USB 链路在 **SuperSpeed**（`DSTS.CONNECTSPD=4`；PC 设备挂 `USB\ROOT_HUB30` 下）；
2. 移植的 gadget 只有 **USB2 高速**（`bcdUSB 2.00`、EP0 64B、Bulk 512B、无 BOS/SS 描述符），SS 枚举必然失败；
3. 因此正确方向是**让链路回落到 USB2**：本次在模块 `dwc3_start()` 之前写 `GUSB3PIPECTL = SUSPHY(bit17) | PHYSOFTRST(bit31)`，把 USB3 PIPE 挂起/复位；
4. kernel_7 日志确认该写入生效（`0xb081402 -> 0x8b0a1402`）、模块 ACTIVE、无错误；剩余问题是 PC 是否重新检测到 USB2 连接（拔插/扫描后再验证）。
